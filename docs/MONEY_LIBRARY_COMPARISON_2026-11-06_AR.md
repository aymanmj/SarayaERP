# مقارنة مكتبة Money والملفات المساعدة

التاريخ: 2026-11-06. المصدر المقارن: `D:/SarayaManager/packages/shared-utils/src`. الهدف: `D:/SarayaERP/server/src/common/utils`. تمت المقارنة على الملفات المحلية الموجودة، ولم تُعدّل ملفات SarayaManager.

## القرار

مكتبة Manager مفيدة كأساس مشترك، خصوصًا حفظ الدقة عند حدود التخزين والنقل والقيم ذات الأبعاد. لكن إحلالها حرفيًا يكسر عقودًا مستخدمة في النظام الطبي. النسخة الطبية كانت تتضمن بالفعل أجزاء مقتبسة منها؛ أُكملت الحماية والاختبارات بصورة انتقائية مع إبقاء التوافق الحالي.

| الجانب | Manager | النظام الطبي والقرار |
|---|---|---|
| الحساب | Decimal منفصل بإعداد precision=40 وHALF_EVEN | نفس السياسة؛ عدم تقريب النتائج الوسيطة دون حد صريح |
| العملة المحلية | LYD بثلاث خانات | الاحتفاظ بها؛ لا تحويل صامت لسياسة تقريب مختلفة |
| مدخلات Prisma | عقود أبسط | دعم DecimalLike واستدعاءات legacy؛ لا اعتبار كل object رقمًا صالحًا |
| الدقة | رفض NaN/Infinity والأعداد الكبيرة غير الآمنة وحدود طول/أس المدخل | أُضيفت الحماية المماثلة؛ القيمة الكبيرة تمر كنص عشري |
| `Money.toDb` | يعيد string | يعيد number حاليًا؛ أبقي العقد. `toDbString` هو الحد الدقيق للمبالغ الكبيرة |
| `Money.toWire` | number إذا حافظ على الدقة وإلا string | العقد موجود؛ يجب أن تتعامل معه DTOs والعملاء بوضوح |
| التحويل إلى number | تحقق صارم في `toNumber` | أُحكم التحقق؛ المساعدات القديمة للنسب تسمح بالتقريب الذي يحفظ قيمة القيد ثلاثية الخانات فقط |
| فصل الأبعاد | مبالغ وكميات ونسب وأسعار صرف | الاستفادة من `MonetaryAmount`, `Quantity`, `Percentage`, `ExchangeRate`؛ مثال: 15 تعني 15% لا 0.15 |
| توزيع مبلغ | حفظ إجمالي الوحدات الصغرى | اختبارات حفظ مجموع التوزيع للموجب والسالب؛ لا تنشأ أو تختفي أجزاء الدينار |
| التاريخ والتفقيط وIBAN والنصوص | مساعدات مشتركة | موجودة في المشروع؛ لم يُثبت باختبار كل أسواق/عملات/لغات استخدامها. لا ادعاء تدقيق شامل لها |

## اختبارات أضيفت

`server/src/common/utils/money.util.spec.ts`: كسور JavaScript، تعادل HALF_EVEN الموجب والسالب، استقلال إعداد Decimal، قيم غير منتهية، قيم كبيرة، نطاق Decimal(18,3)، تحويلات دقيقة، حفظ مجموع التوزيع، فصل العملات والكميات والنسب واتجاه سعر الصرف. نجاحها لا يثبت أن كل خدمة مالية تستخدم المكتبة بصورة صحيحة.

## ما بقي قبل التوحيد الشامل

1. جرد حسابات كل الوحدات التي تستعمل `Number`, `parseFloat`, `Math.round` أو حسابات سعر × كمية خارج Decimal، ثم ترحيلها مع حالات مالية مرجعية.
2. تعريف عقود API للمبالغ كنصوص عشرية في إصدار واضح؛ تحديث العميل والمحمول والتقارير قبل تغيير `toDb` أو `toWire` في المستهلكين.
3. نشر الحزمة المشتركة محليًا ضمن workspace بعد توحيد build والاعتماديات والإصدارات؛ تجنب نسخ متباعدة تتطور كل واحدة منفردة.
4. مطابقة الفواتير والخصم والضريبة والتأمين والمردودات والتسويات والعملات مع محاسب؛ المكتبة الحسابية لا تحدد السياسة المحاسبية أو التنظيمية.
5. عدم افتراض أن null أو النص الفارغ يساوي صفرًا في حقول إدخال مطلوبة؛ التحقق مسؤولية DTO. التوافق القديم في المكتبة ليس بديلًا عن التحقق الوظيفي.
