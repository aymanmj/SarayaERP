# MPI Governance — الحوكمة الوطنية لسجل المرضى

## 1. المبدأ الأساسي

> **الربط الوطني تلقائي دائماً — لا يقرره أحد.**

عند تسجيل أي مريض جديد في نظام السرايا، يتم **فوراً وتلقائياً**:
1. البحث عن المريض في السجل الوطني (`GlobalPatient`) بالرقم الوطني أو الهاتف
2. إن وُجد: ربط الملف المحلي بالسجل الوطني الموجود
3. إن لم يُوجد: إنشاء سجل وطني جديد وربطه

هذا السلوك **لا يمكن تعطيله** — وهو جوهر بنية MPI.

---

## 2. ما تتحكم فيه المنشأة: OTP لمشاركة البيانات

ما تقرره المؤسسة الأم / المستشفى / الهيئة الصحية هو:

**هل يجب الحصول على موافقة صريحة من المريض (عبر OTP) قبل مشاركة بياناته مع المنشآت الأخرى؟**

| الإعداد | السلوك |
|---------|--------|
| `mpi.requirePatientOTP = false` (افتراضي) | يُربط المريض فوراً، ويبدأ تبادل البيانات مباشرة |
| `mpi.requirePatientOTP = true` | يُربط المريض فوراً، لكن يبقى `MpiConsentRecord.status = PENDING_OTP` حتى يؤكد المريض عبر OTP |

---

## 3. دورة حياة الربط الصحيحة

```
تسجيل مريض جديد (في أي منشأة)
        │
        ▼
بحث تلقائي في GlobalPatient
(بالرقم الوطني / رقم الهاتف)
        │
   ┌────┴────┐
موجود      غير موجود
   │           │
   │      إنشاء GlobalPatient جديد
   │           │
   └────┬──────┘
        │
   ربط Patient المحلي بـ GlobalPatient
   (globalPatientId دائماً مُعبَّأ)
        │
        ▼
   هل mpi.requirePatientOTP = true ؟
        │
     نعم ──► MpiConsentRecord { status: PENDING_OTP }
        │         الربط قائم لكن مشاركة البيانات معلّقة
        │         حتى يتحقق المريض عبر OTP
        │
     لا  ──► MpiConsentRecord { status: ACTIVE }
              مشاركة البيانات فورية
```

---

## 4. حالات سجل الموافقة (MpiConsentRecord.status)

| الحالة | المعنى |
|--------|--------|
| `PENDING_OTP` | الربط تم، OTP أُرسل للمريض، ينتظر التأكيد |
| `ACTIVE` | الربط والمشاركة فعّالان |
| `REVOKED` | سحب المريض موافقته على المشاركة |
| `EXPIRED` | انتهت صلاحية الموافقة |

---

## 5. إعداد OTP — التسلسل الهرمي

يقرأ النظام الإعداد بالأولوية التالية:

```
OrgSetting (mpi.requirePatientOTP)    ← إذا كان المستشفى تابعاً لمنظومة
    │  إن لم يوجد ↓
SystemSetting (mpi.requirePatientOTP) ← للمستشفى المستقل
    │  إن لم يوجد ↓
false (افتراضي — مشاركة مباشرة)
```

**الواجهة:** إعدادات المنشأة → "الربط الوطني MPI" → "اشتراط موافقة المريض عبر OTP"

---

## 6. سياسة الاحتفاظ بالبيانات (DataRetentionPolicy)

| الفئة | الاحتفاظ |
|-------|----------|
| سجلات المرضى النشطة | 10 سنوات |
| سجلات غير النشطين | 7 سنوات |
| السجل الوطني MPI | 25 سنة (إلزامي وطنياً) |
| سجلات التدقيق | 10 سنوات |

## 7. سياسات وإجراءات إلغاء الموافقة (Consent Revocation Policy)

يتيح النظام للمريض سحب موافقته على مشاركة بياناته الإقليمية (Consent Revocation) في أي وقت وفقاً للسياسات التالية:

1. **إيقاف المشاركة فوراً (Immediate Access Termination):**
   بمجرد تغيير حالة السجل إلى `REVOKED`، يتم إيقاف أي وصول جديد لملف المريض من أي منشأة أخرى عبر الـ MPI.
2. **سحب الـ Tokens النشطة:**
   يقوم النظام بإبطال رموز الوصول (`consentToken`) التي تم إصدارها مسبقاً وتُستخدم حالياً لطلب البيانات.
3. **أثر الإلغاء على البيانات المحفوظة مسبقاً:**
   - الإلغاء يؤثر على *المشاركة المستقبلية* فقط.
   - إذا تم تنزيل سجلات طبية (مثل نتائج تحاليل أو أدوية) وحفظها محلياً في مستشفى آخر خلال فترة سريان الموافقة (`ACTIVE`)، تبقى تلك السجلات في النظام المحلي لذلك المستشفى وفقاً للوائح السجلات الطبية.
4. **تفعيل الموافقة مجدداً:**
   في حال رغب المريض بإعادة تفعيل المشاركة، يجب المرور بدورة إرسال وإدخال OTP جديدة تماماً.

---

## 8. ملاحظة تقنية: `mpi.enableFederation`

هذا الإعداد **لا يوقف الربط الوطني**. يستخدم فقط لتحديد هل ترسل المنشأة بيانات اختيارية إضافية (مثل بيانات اللقاحات) لهيئات خارجية. **الربط الأساسي عبر GlobalPatient دائماً إجباري**.
