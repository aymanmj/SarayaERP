# سلامة صرف الصيدلية والمحاسبة — 2026-11-08

المرجع الرئيسي هو [السجل الموحد](REMEDIATION_REGISTER_2026-11-07_AR.md). هذه دفعة محددة ضمن FIN03B وFLOW04 وCLN01 وCLN02 وOPS03،ولا تغلق وحدة الصيدلية أو بقية خارطة التطوير. اكتمل التحقق الآلي ضمن النطاق أدناه؛القبول السريري والمالي والبصري لم ينفذ.

## المشكلة والإصلاح

كان صرف POS يحفظ المخزون والفاتورة والدفع قبل تنفيذ قيود الإيراد والتحصيل،وكان قيد تكلفة الصرف يُنشأ من حدث لاحق يفشل بصورة مستقلة عن الصرف. أصبح تسجيل الصرف والتشغيلات وحركات المخزون والرصيد الإجمالي وتكلفة البضاعة والتدقيق الإلزامي في معاملة PostgreSQL واحدة. يضيف POS الفاتورة والتحصيل وقيديهما في المعاملة نفسها. فشل أي منها يعيد العملية كاملة. لا ينشئ إشعار تحديث الواجهة أي قيد محاسبي؛الإشعار بعد الالتزام وأفضل جهد،وفشله لا يعيد للمستخدم خطأ دفع بعد تحصيل ناجح. الإشعار لا يتضمن تكلفة الأدوية.

أضيف قفل متسق مع كتّاب المخزون المعدلين،وأقفال المريض والحالة والوصفة والأصناف بترتيب ثابت. يرفض المساران وصفة خارج المنشأة أو علاقات مريض/حالة غير متسقة،وصنفًا غير نشط أو محذوفًا أو غير دوائي،وحالة علاج مغلقة،وصفة غير ACTIVE أو غير معتمدة صيدلانيًا،وقصور التشغيلات أو الرصيد الإجمالي. تحديث التشغيلات مشروط بالإصدار والكمية،وتحديث الرصيد الإجمالي يزيد الإصدار. يبقى فحص انتهاء الصلاحية في اختيار FEFO. إعادة الصرف تُرفض،ولا تُعاد نفس النتيجة كعقد idempotency بمفتاح عميل.

الحسابات المالية للصرف تستخدم Money وDecimal. يُقرب إجمالي كل بند مرة واحدة،ثم يوزع على تشغيلاته بأكبر البواقي،بحيث يساوي مجموع قيم الحركات والقيد القيمة المثبتة. المثال المستقل:دواء سعره3.333 وتكلفته2.345 وكمية1 موزعة على تشغيلتين0.500؛المجموعان3.333 و2.345،دون فقد أو زيادة درهم. جُمعت إيرادات recordInvoiceEntry وحصص الفاتورة وفروقها باستخدام Money بدل الحساب العائم. هذا لا يعني ترحيل كل AccountingService أو كل PharmacyService.

يشترط الصرف وجود خدمة PHARMACY-DRUGS للفوترة؛لا يتجاهل رسم الصرف عند فقدها. POS محدود بسداد كامل دون ارتباط تأمين،وبطرق CASH/CARD/TRANSFER المدعومة محاسبيًا. يتطلب جلسة صندوق OPEN،ويربط الدفع النقدي بعهدتها،ويرفض الجلسة قيد العد أو المغلقة. لا يمثل تسجيل CARD/TRANSFER إثبات تسوية مصرفية أو تكامل بوابة دفع.

الصرف الجزئي وتغيير الصنف لا يجوز تحويلهما ضمنيًا إلى إكمال للوصفة. لذلك يرفض المساران تغيير الصنف أو الكمية،والبنود المجهولة أو المكررة أو الفارغة أو الناقصة. عطلت الواجهة تعديل الصنف والكمية،وأوضحت القيد التشغيلي ومتطلبات التحصيل؛تنفيذ دورة بدائل وصرف جزئي يحتاج اعتمادًا سريريًا وتتبع المتبقي والجرعات والمرتجعات. لا يعني تعطيل الحقول اكتمال هذه القدرة.

## المتبقي والمرحلة التالية

1. أُنجز مصدر مخزن الصيدلية الصريح وصلاحياته وتدقيقه والتحقق المتزامن من نشاطه في[الدفعة اللاحقة](PHARMACY_SOURCE_POLICY_2026-11-08_AR.md). أزيل اختيار المخزن بالاسم أو أي مخزن نشط؛يلزم تعيين المصدر قبل أول حركة. لا يحل ذلك بقية كتّاب الكمية والتقييم أو قبول التشغيل.
2. إكمال توحيد كُتّاب الكمية والقيمة:حركات الصيدلية اليدوية والجرد والتسويات والاستلام،واختبارات التنافس بينها وبين الصرف والتحويل والشراء. اختيار FEFO لا يثبت تقييم FIFO؛تكلفة الصرف الحالية تستخدم Product.costPrice وتبقى طبقات التقييم وربط حسابات الأصناف والمطابقة المحاسبية مفتوحة.
3. نقل حسابات وعرض الواجهة وعقود المبالغ إلى عقد Money مشترك دقيق،ثم باقي التقارير والمحمول. ما زالت شاشة الصيدلية تحسب المعاينة بالأرقام العائمة؛الخادم يحسب القيمة النهائية ويرفض سدادًا مخالفًا،لكن ذلك ليس قبولًا لتجربة الاستخدام أو اكتمال FLOW04. تبقى عقود DTO الشاملة وحالات HTTP والصلاحيات لكل endpoint مطلوبة.
4. قبول صيدلي ومحاسب لحدود يوم انتهاء الصلاحية والحجر والاستدعاء والصرف الجزئي والبدائل والمرتجعات والتأمين والأدوية المقيدة،وقبول الواجهة بالأدوار. الاختبارات هنا تستدعي الخدمة داخل AppModule ولا تمثل اختبار متصفح أو قبولًا بشريًا أو مصفوفة صلاحيات HTTP كاملة.
5. الإشعارات بعد الالتزام أفضل جهد وليست Outbox مضمونة. تبقى متانة الأحداث العامة والتعافي والأداء ومراجعة ترتيب الأقفال عبر كل الوحدات ضمن OPS03 وQA01. لا تعني أقفال هذه الدفعة إثبات سلامة جميع الكتّاب أو اعتماد حمل إنتاجي.

بعد إتمام مصدر مخزن الصيدلية في الدفعة اللاحقة،الخطوة التالية ذات الأولوية:الحركات اليدوية والجرد والتسويات،مع استمرار نقل المال في بقية النظام وبقاء جميع بنود السجل الموحد.
